# 16次检查完成，但重复返回不能当作独立验证

这轮16次模型请求已经实际完成。关键发现是：**同一种输入的4次返回，回答编号、生成时间和回答正文都相同。** 因此不能把“4次答案一样”解释成模型独立思考了4次、选择很稳定。接口为什么这样返回，目前还不能从本地记录确定。

| 输入 | 原策略 | 指定参考价 | 返回基本面 | 返回技术 | 未提交、缺失或无效 |
|---|---|---|---|---|---|
| A（0000） | 基本面 | 95 | 0 | 4 | 0 |
| B（0100） | 基本面 | 105 | 4 | 0 | 0 |
| C（1000） | 技术 | 95 | 4 | 0 | 0 |
| D（1100） | 技术 | 105 | 4 | 0 | 0 |

这里的“基本面”是比较价格与指定参考价，“技术”是根据价格走势作判断。四种输入的当前价都是95，给定基本面基准表现较好，群体多数也都采用基本面。表内数字是收到的回答次数，不是独立生成次数，更不是真人数。

全部输入和顺序在发送前固定，每种输入各处于第1至第4位置一次。16条均记录为成功返回，没有本地缓存命中、重试、补问或格式修复。但全组只有4个不同回答编号、4段不同回答正文；这也不能证明存在4次独立生成。每种输入的第2至第4次完整返回相同，第1次仅有附加元数据不同，不能写成16份完整返回全都相同。本地“未命中缓存”只描述我们的程序，不能保证学校接口或上游重新生成了答案。

本轮返回里，原策略为基本面时，把参考价从95改成105，目标由技术变为基本面；原策略为技术时，两种参考价都返回基本面。这些对比按原计划保留在逐组结果里，但不能据此声称找到了稳定的心理规律。参考价是研究者给定的数值，不是真实价值的证明；原策略变化也同时修改了记忆中的策略标签，不能直接解释为真实投资习惯。

此前B输入曾在完整提问和模型设置相同的情况下，先返回基本面、后来返回技术。本轮又返回基本面，不会推翻那两条旧记录；旧回答也没有混进本轮16条的计数。“多数人采用基本面”是给定信息，把它解释成“群体智慧”则仍是未经验证的推测。

程序上修复了一处独立子agent发现的漏洞：原先跨组异常可能等16条全部发送后才发现，现在每组结束先核对全部已有记录，通过后才继续。反例验证中，第2组出现跨组时间冲突时，程序在8次模拟发送后停止，后两组不发送，第2组也不标成接受。42项本地检查通过，其中11项新检查由独立子agent再次验证。原输入、问题和发送次数没有因此改变。

对照RP，本轮推进的是“怎样可靠地检查AI选择”，尚未证明“AI更像真人”，也没有新增整个市场更真实的证据。没有打开保留的真人测试数据，没有恢复暂停的批量优化或运行新市场。

独立子agent已从原始日志完成复算，验收了这16条执行及用量，但确认独立重复生成的目的未达到。它还核对了本地缓存和客户端代码：相同编号、时间和正文已经出现在记录的HTTP返回里，具体发生在哪一层仍不确定。下一步先查学校接口已有说明或记录，弄清怎样设计有解释力的复测，不继续密集重复同一问题，也不加随机文字求新答案。累计已用**55/100次**，还剩45次，沿用已有授权，不逐批确认。本轮不为相同答案或返回复用补发请求。
