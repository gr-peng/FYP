# 成交活动 v1 后的最小下一步：分开检验零概率与盘口增量

日期：2026-10-11。状态：设计建议，尚未实现或拟合新模型。本次只读取已公开给研究流程的 November v1 结果、既有配置和辅助数据协议；没有读取辅助 development 行情、分布、特征或模型分数。v1 代码、配置和结果保持原样。

建议顺序是：**先把更多完整自然日作为共同评价基础；下一版只增加 hurdle NB 这一种分布假设，保留现有特征；更丰富的活动滞后留作另一个有明确边界的实验。** 更多日期和更合适的计数分布解决不同问题，不能互相替代。当前证据不能支持“盘口没有用”，也不能支持“必须换 hurdle 才能模拟真实市场”。

## 2. 为什么优先检查 hurdle，而不是直接增加“零膨胀”

当前 NB2 有：

```text
E[Y|x] = mu(x)
Var[Y|x] = mu(x) + alpha * mu(x)^2
P(Y=0|x) = (1 + alpha * mu(x))^(-1/alpha)
```

v1 的 0 ms 基线 `alpha=2.39826`。同一个离散参数同时影响正计数尾部和零概率；用较大的 alpha 容纳爆发性大计数，可能导致模型给零事件太多概率。这里的“零偏少”只指**相对于已拟合 NB2 预测**，不是说实际市场天然只有一个“零不足机制”。遗漏活动状态、条件均值链接不合适、正计数分布不合适、非平稳性及档案覆盖假设都可能贡献这种现象。

不要把平均 mu 代入 NB2 的零概率公式冒充平均预测零比例：应计算逐样本 `P0_i` 后取平均。非线性使二者不同。也不能把开发零比例 10.08% 直接设成新模型的零概率；那会用评价标签进行再校准。

对固定的基础计数分布，标准零膨胀混合满足：

```text
P_ZI(0|x) = pi(x) + (1 - pi(x)) * P_count(0|x) >= P_count(0|x)
```

所以，在当前基础 NB2 已过度预测零的情况下，仅给它叠加非负“额外零”不是有针对性的修复。ZIP 同时改成 Poisson 正计数部分，不能据此保证仍能容纳厚尾。这个不等式不证明重新估计全部参数的 ZINB 在任何数据上都一定更差；它只说明“看到零误差就用零膨胀”在本例方向不明确。hurdle 将是否为零与正计数大小分开，也允许相对于基础计数分布的零减少。[Zeileis、Kleiber、Jackman：Regression Models for Count Data in R](https://www.jstatsoft.org/article/view/v027i08)，[statsmodels 的 hurdle 与 zero-deflation 示例](https://www.statsmodels.org/stable/examples/notebooks/generated/count_hurdle.html)。

最小候选使用 logistic 概率 `p(x)=P(Y>0|x)`，以及零截断 NB2：

```text
P_H(0|x) = 1 - p(x)
P_H(k|x) = p(x) * f_NB(k; mu(x), alpha) / (1 - f_NB(0; mu(x), alpha)), k >= 1
E_H[Y|x] = p(x) * mu(x) / (1 - f_NB(0; mu(x), alpha))
```

这里 `mu` 是截断前 NB 的均值参数，既不是正计数条件均值，也不是完整 hurdle 均值。直接用 `p*mu` 计算 MAE/均值校准会算错。正计数部分必须拟合**零截断似然**；删除零后普通拟合 NB 也不正确。hurdle 只是统计分解，不意味着已识别两类真实交易者或两种市场机制。

官方 statsmodels 示例说明了两部分结构，但其现成 `HurdleCountModel` 所列零部分并非直接的 logistic 子模型；若按本文方案实现，需明确验证 logistic 与零截断 NB 的组合，不能假定一个同名 API 已实现完全相同的模型和正则。[statsmodels 模型与预测量说明](https://www.statsmodels.org/stable/examples/notebooks/generated/count_hurdle.html)。

## 3. 下一版的有限候选：四个主模型，一个负对照

本表是建议冻结的 v2 范围，须在任何 aux development 行情查看之前形成新协议并提交。它不修改 v1，也不是宣布这些新模型已经胜出。

| ID | 分布 | 可用特征 | 预定比较目的 |
| --- | --- | --- | --- |
| N0 | 现有 NB2 | 现有 UTC sin/cos、最近已知成交数/量 | 在新自然周重新拟合的基线 |
| N1 | 现有 NB2 | N0 + 现有四个盘口特征 | 复核旧盘口增量诊断 |
| H0 | logistic + 零截断 NB2 | 与 N0 完全相同，两部分均使用 | H0−N0：解除零概率约束是否改善分布预测 |
| H1 | logistic + 零截断 NB2 | 与 N1 完全相同，两部分均使用 | H1−H0：更合适分布下是否仍有盘口增量 |
| Hnoise | 与 H0 相同 | H0 + 四维独立伪随机特征 | 检查增加同等数量特征是否出现偶然增益或流程问题 |

Hnoise 预先固定一个种子，例如 `20261011`，通过种子、已知 UTC 信号桶和特征编号确定四维标准正态噪声；不读取未来行情、不使用目标、不尝试多个种子择优。所有变换、生成算法和特征顺序一起冻结。它是无额外市场信息的负对照，不是校准后的显著性检验；单次噪声模型偶尔优于 H0 并不证明泄漏。若 H1 的小增益与噪声对照相当，应降低“发现盘口机制”的解释强度并检查流程。

不做将整个开发日盘口随意打乱的“可交易模型”：这可能把未来状态带入当前输入。若将来用整日打乱，只能单列为离线破坏关联实验，不能与满足 available-at 的预测比较混为一谈。固定很久以前的盘口也不是真正无信息零假设，慢变活动和市场状态仍可能提供信息，暂不增加这一对照。

所有五个模型都按已定 **0/1,000/5,000 ms** 三种延迟单列，共 15 个固定拟合对象；全部报告，不通过 aux development 选最佳延迟、分布或种子。关键机制比较只有 H0−N0、N1−N0、H1−H0；Hnoise−H0 用于警示。更改这些比较就是新协议，而不是当前版本内的自由搜索。

共同约束如下：

- 沿用 v1 可用时间、最新已知完整成交秒、同段完整目标秒、重复目标去重与五档双侧覆盖规则。所有模型使用同一延迟下的同一训练/评价行集合，包含负对照；报告拒绝覆盖比例。全体信息增加同一额外延迟，延迟等待期间不刷新输入。
- 保留现有八个潜在特征的定义，不增加交互、样条、weekday 特征或更长历史。标准化只在 aux train 的共同样本上计算；H0/H1 的两部分共用各自训练标准化，不用仅正计数子集另算归一化。
- 沿用 `lambda=0.01`、NB2 alpha 数值范围 `[1e-4,1000]` 和明确的优化失败退出规则。截距与 alpha 不惩罚；边界解和未通过梯度验收均如实记录，不能隐藏备用拟合。
- hurdle 冻结目标为 `全体 N 行的平均负 log probability + lambda/2*(gate斜率平方和 + count斜率平方和)`。如果两部分分开优化，正计数部分似然仍除以总 N；不能悄悄改成除以正计数个数后仍用同一正则。logistic 项、截断归一项采用数值稳定形式，并测试概率和为 1、正确均值、零样本、厚尾、解析/数值梯度和优化失败。

这些数值是拟议的固定实验规格，不是已验证最优设置。若 aux train 阶段发现实现错误，可修复并重冻全部产物；不能看 aux development 表现后把改参称作错误修复。

## 4. 更丰富滞后状态：有理由，但暂不同时加入

最近一个成交秒可能只是有噪声的活动状态代理。较长的历史可能吸收慢变活动、减小残余离散程度，并同时改善零概率和均值；因此 hurdle 不是唯一可行解释。另一方面，增加滞后与修改分布一起发生，会使改进来源难以分辨，且扩张开发选择空间。

当前建议不将它纳入上述 v2。若随后另立协议，最小扩展可只增加一个预定窗口，例如**截至最新已知完整成交秒的过去 60 个连续秒平均成交笔数的 `log1p`**。窗口的最后一秒也必须已可用，前 60 秒均在同一 joint run；缺口不补、开头不足不补。为公平比较，原始短历史基线也在同一个 60 秒可用样本掩码上重新拟合和计分。不同时搜索 5/10/30/60/300 秒、多个 EWMA 衰减、深度半径和正则。

如果在开启 aux development 之前决定把这个单一滞后加入 v2，必须先修改并提交候选清单、比较顺序和全部固定规格；不能开启之后再声称它预先计划。否则，任何依据 aux development 结果提出的滞后版本都应将该周视为已使用开发信息，安排新的未查看评价样本；原 11 月事件测试不用于快速筛选。

### 阶段 A：fit，仅允许 aux train

独立 fit 入口应对允许的 split/day 做硬门控，甚至在进程中调用 reader 请求 development 时也报错。训练可检查七个训练日的分布、覆盖和残差，但不触碰辅助开发周的特征/分数。不把 reader 本身支持 development 当成 fit 入口的权限。

一次生成并冻结完整模型包，至少包括：

- 全部 15 个对象的系数、alpha、两部分参数、训练标准化及固定特征顺序；固定噪声算法/种子；优化结果、梯度、边界标记、训练样本数。
- 训练日期、样本掩码/样本 hash、训练输入/特征/当前 audit run 与处理源码 hash、aux 数据配置 hash、新模型协议 hash、代码提交与源码 hash、运行库版本。
- 明确的目标/延迟/历史可用时间规则、评价指标及 count 分组规则、缺失文件和失败对象处理规则；所有供评价参考的训练分位数在此保存。
- 不可覆盖的 artifact manifest、模型内容 hash、冻结时间及独立审查结果。必须先通过合成数据、数值参考和时间错位反例，才能打开辅助开发行情。

不要重用 v1 `run_probe` 的“一次函数中先读 train 和 development，再拟合”的工作方式来声称两阶段隔离。新设计应让 fit 根本不打开开发市场数据，并让 evaluate 可以只靠模型产物工作。

### 阶段 B：evaluate，仅加载冻结产物

核对模型包、协议、代码、数据配置 hash 后，再授权生成/消费 aux development 特征；记录首次市场数据访问时间。只通过当前成功审计的 reader 读取。evaluate 不调用优化器、不估计标准化、不调 alpha、不重新训练 logistic 截距、不用开发零比例做校准；缺失训练参数即失败，不能临时拟合补齐。

按冻结清单处理全部七日，全部模型、延迟和共同样本都完成后统一汇报。每日处理可以分批，但不能看某一天的评分后换模型再继续剩余日期。若档案/特征/某模型失败，保留失败状态并明确哪些比较不可完成，不删除不利日期或自动替换自然周。

最终评价产物另绑定开发输入/特征/audit hash、共同样本 hash、冻结模型包 hash与评分源码 hash；采用新路径、不可覆盖。应有测试证明 `evaluate` 在所有 `fit`/优化器被替换成报错函数时仍能正常评分，及 `fit` 对任何 development reader 调用立即失败。原 11 月 5—7 日的最终事件测试继续封存。

## 6. 预定评价和明确反例

主指标继续是完整计数 PMF 的平均 log score。hurdle 的逐样本分解可明确写成：

```text
binary_score = 1[Y=0]*log(1-p) + 1[Y>0]*log(p)
positive_score_contribution = 1[Y>0]*(log f_NB(Y) - log(1-f_NB(0)))
full_score = binary_score + positive_score_contribution
```

对 NB2 也可用其隐含 `p=1-P_NB(0)` 作同样分解。这是相同全样本分母下的可加分解；仅正样本平均分可以另报，但不要拿它与全样本分直接相减。原 v1 汇总 JSON 没有逐样本二元 log score 或正计数分项，因此本文件不反推出尚未计算的分数。

预先同时报告：

- 全周逐秒加权 log score 和七个逐日差值；另报日均差值、最差日、正负日数以及固定三小时块的描述，不能选择最漂亮的聚合方式。七天相邻行情也不是七个完全独立制度，不给 i.i.d. 秒级标准误或“统计显著”的单周完成结论。
- `P(Y=0)` 的逐日/三小时校准、二元 Brier 与二元 log score；小计数概率组固定为 `0, 1, 2, 3–5, 6–10, 11–20, 21–50, 51+`，比较逐行预测概率相加后的组频率与实测比例。分组是设计选择，不根据开发计数分布调整。
- 完整均值校准、原定义均值 MAE，及预定的中位数 MAE作为补充；分开记录正计数条件均值和全体均值。只有零比例接近而均值/尾部严重失真，不足以说分布已拟合好。
- 三个延迟分别计分；不同延迟的边界样本略有不同，不把跨延迟差值解释为纯延迟因果效应。每个延迟内部各模型必须完全同样本。

可证伪结果包括：

1. **H0 零校准改善，但全 PMF log score 下降或正计数部分恶化。** 这表明单独修零没有解决整体分布，不能只展示零比例作为成功。
2. **H0 优于 N0，而 H1 与 H0 无稳定差异。** 支持分布结构改进，仍不支持盘口增量机制；不因此增加 prompt。
3. **H1 的改善只集中于一个交易日、最短延迟，或与噪声对照同量级。** 作为脆弱关联保留，不宣称稳定、可交易或因果机制。
4. **更长历史的另立版本改善 NB2，使 hurdle 优势消失。** 与“遗漏慢变活动状态”解释相容，反驳“只有独立零门控才有效”的强结论，但不能据此倒推当前 v2 已验证。
5. **全部模型在新周都失校准。** 说明当前条件信息/分布仍不足；记录失败并另立新方案，不继续在同一开发周无限尝试参数或换日期。

即使所有计数诊断改善，也只支持“下一秒活动分布的一个条件组件更合理”。它尚不能生成自洽价格/深度路径，不能解释新增与撤单、重建 L3 排队、验证代理冲击或证明整套市场模拟已完成。
