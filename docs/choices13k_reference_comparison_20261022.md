# 进度：人群参考信息已接入真实模型，但本题两组结果相同

**本轮16次真实请求全部完成，两组都选了稳赚1的一边；另一边只会亏2或11。** 正确配对参考与打乱参考的结果完全一样，但这道题一边明显更好，还没有检验遇到真正两难选择时，正确参考是否有帮助。

我们固定一道目标题，让两种方法看到同样的三道参考题和同样的一组人群选择比例。一种把比例配对正确，另一种按事先定好的顺序打乱。两边都覆盖四种显示方式，每种问两次，共16次；字母和前后位置都会变。

| 本次结果 | 正确配对参考 | 打乱配对参考 |
|---|---:|---:|
| 收到的有效回答 | 8份 | 8份 |
| 选择原方案A | 8/8 | 8/8 |
| 选择原方案B的比例 | 0% | 0% |
| 与人群原B选择比例的差距 | 2.5个百分点 | 2.5个百分点 |

本题人群中97.5%选择原方案A，2.5%选择原方案B；这个比例只在本地用于核对，没有给模型看。模型收到的16份回答都选原方案A，改变字母和前后位置后也是如此。同一种输入问两次，8组都没有出现前后相反的回答。

**这次没有观察到正确配对参考比打乱参考更好。** 这道题不需要在风险和收益之间作困难取舍，人群本来也高度一致；本次也没有“不提供参考”的对照。因此，我们只能说这两种配对方式在这道题上结果相同，不能说模型已经学会人的偏好或参考信息完全没有作用。

发送前，独立审阅找出了两处问题：改动过的本地材料可能蒙混过关，测试回答也可能被误标为真实回答。两处已修复，94项本地检查通过，独立审阅者也运行了94项检查并验收了16份完整请求。修复没有改变实际发送的题目、参考资料或比例，初版已保留。

真实运行已结束，没有重试或补问。实际发送内容和返回身份与事先固定的请求完全匹配。16份返回没有发现相同的“返回编号、生成时间、回答内容”组合，但这不证明后台独立生成，也不证明缓存设置生效。独立审阅者已逐条复核三类各16条原始记录，并绕开比较工具手算确认结果，正式验收通过。

对照RP，本轮完成的是“把人群参考信息接入模型，并在相同条件下实际比较”。还没有证明它让模型整体更像真人。这些资料记录的是风险选择实验中的人群汇总比例，并不是个人在市场中连续交易的记忆；从个人决策到策略变化、再到市场是否更真实，仍未验证。
