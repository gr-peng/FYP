# 加密市场真实性：持续研究协议

用户要求先做加密市场，持续寻找真实模拟方法、自行寻找缺失数据，并由独立agent评测完成度和提出idea。此目标保持开放；取得数据、通过工程测试或跑完一组实验，均不代表整体完成。上轮双事件实验的负结果继续保留。

独立审查已指出：当前现金/库存撮合内部一致，但真实LOB重建、外部成交验证、内生价格真实性和真人行为增益都未建立。新的工作按这四层分别验收。独立评测agent不得把自己的建议当成验证结果，最终须检查原始数据、实现及留出结果。

截至2026-10-11，已下载2024年11月1—7日Bybit BTCUSDT的7份500档L2快照/增量ZIP和7份逐笔成交GZIP，总计2,632,504,549字节（约2.63GB）。官方历史页面JavaScript调用的`list-files`接口直接返回档案URL；14份文件的来源、长度、ETag、本地SHA256及下载时间均已记录。原档案在`data/raw/crypto_microstructure_20261011/`，官方来源链在`outputs/crypto_research_20261011/data_search/`。下载成功不等于全文件语义审计通过。

该品种是Bybit的USDT线性永续合约，不是此前的Binance现货，也不是链上市场。500档是可见价格档位聚合数据，不能称为全市场逐单LOB。研究其可见盘口和订单流时，必须保留这一场所、合约和观测范围。

另已从Bybit官方V5接口归档同周[标记价格分钟K线](https://bybit-exchange.github.io/docs/v5/market/mark-kline)、[指数价格分钟K线](https://bybit-exchange.github.io/docs/v5/market/index-kline)及[历史资金费率](https://bybit-exchange.github.io/docs/v5/market/history-fund-rate)。来源响应、请求时间范围、hash和覆盖审查位于`outputs/crypto_research_20261011/contract_sources/`；覆盖记录为标记/指数各10,080分钟和21次资金费结算。资金费率只能在对应结算时点应用，分钟high/low/close不能提前到分钟开头提供给代理；这些数据不能恢复逐tick标记价或精确强平时序。

独立的`LinearPerpetualAccount`账本已实现USDT钱包、带符号合约仓位、开仓成本、已实现/未实现盈亏、费用和资金费核算。它目前是实验账户约束，不是已经验证的2024年Bybit账户制度：历史风险档位、完整费用/最小名义金额变更、账户及保证金模式、挂单保证金预留、强平和ADL路径仍未完成验证。当前API参数不能冒充目标周参数，独立账本的存在也不代表它已接入并验证完整市场模拟。

配置为`config/crypto_microstructure_20261011.json`。完整时间块提前固定：11月1—3日训练，11月4日开发，11月5—7日事件最终检验。此前11月4—7日各约一分钟文件开头只用于来源和格式探测，不用于选模型。最终检验允许归档、CRC、schema、时间覆盖与数据质量检查；不得在模型和评价方法冻结之前生成价格/深度分布报告或模型分数。既有真人金融最终测试16场仍不打开。

来源审查曾记录整周资金费率范围摘要，该摘要属于已经观察的信息，不能用于参数选择；不能将这一数据集描述为从未查看过任何测试期描述值。事件期订单簿/成交市场分布和模型评价仍封存，当前阶段不导出其建模特征，不因文件已下载而解除门控。

原始URL、响应长度、ETag、SHA256和下载时间保留。ETag不当作内容SHA256；本地hash只是归档完整性，不冒充发布者签名。ZIP/GZIP解压CRC须通过。无法恢复的时间/序列异常要保留并切段，不能前向填补为无缺口。Bybit `seq`跨多个盘口深度，不能要求每条加一；`u`的单步变化只能作为单条订阅档案的连续性诊断，不能替代独立快照或校验和证据。

本次格式修正来自训练档案检查：按日命名的LOB文件尾部会包含次日约2秒消息。首次`ec620a4`训练审计把11月1、2、3日尾部18、19、19条消息误报为日期异常，原输出已保存在`outputs/crypto_microstructure_20261011/initial_ec620a4_audit/`。这份历史审计及其特征不能作为修正后验收结果；修正代码已提交为`f7f0d2e`，全量重审已完成，7份LOB结构检查及7份成交有效性/CRC检查通过。旧输出不删除，也不把格式误报解释成真实市场中断。

日期边界前后60秒容差只用于完整读取档案、CRC和格式/序列审查，不扩展训练或检验日期。导出时只允许命名日期内的桶，并要求`available_at_ms < 次日00:00:00 UTC`。每个有效segment从snapshot开始，逐步累计已使用消息的最大publication `ts`；秒桶的可用时刻为`max(bucket_ms + 1000, segment累计最大ts, 确认该桶结束的后续消息ts)`。初始快照、缺口、重置或文件末尾形成的不完整桶不得当成完整一秒。时间以`cts`归桶，不意味着数据在`cts`当时已经可观测。

下游消费者必须同时核对本次逐文件审计的`status=complete`、有效`audit_run_id`和`features_published=true`，以及实际输入文件、冻结配置、输出特征的hash和输出行数。仅有Parquet文件、旧成功manifest或批任务的`complete`都不够。批任务完成仅表示审计执行结束，仍须读取数据质量与有效segment说明。若预检查或重处理失败，必须让本次失败状态覆盖旧授权，禁止继续使用旧manifest宣称新结果成功；该预检查失败遗留manifest漏洞已在`f7f0d2e`修复，并经独立审查：任何前置检查前先原子写入running/不可读状态，失败发布failed，消费者另行重验原始字节。新全量审计已完成。拒绝最终检验特征读取的门控不变。

价格和数量采用精确整数存储，尺度100与1000来自样本表示精度，不称为已证实的2024年交易最小步长。snapshot替换整本，delta数量为绝对数量，零删除。聚合L2无法唯一分解新增/撤单/改单，更新间发生的事件也可能相抵。拟合对象须称为可见深度变化，不能伪称已识别逐单到达强度。

第一层验收：重建期间不负量、不交叉，按场所语义处理重快照、乱序及失效；有独立快照/校验或明确记录缺少该证据。第二层：主动单逐档消耗可见数量，超深度不能无依据全成；被动队列只能在有数据支撑下验证，否则报告假设范围。历史影子单不能修改后续真实绝对深度后，又宣称有真实反事实冲击。

第三层先比较固定LP、训练期拟合的简单可见订单流、状态条件化过程。生成时只读取起始状态，不能输入真实后续价格或订单流来维持曲线。指标同时覆盖价差/深度/失衡、成交与更新率/聚集、秒与分钟收益/零收益/绝对收益自相关、订单流与价格联合关系。阈值须依据训练期跨日自然变化制定并在最终检验前冻结；不能事后挑选最像的指标或种子。

第四层才检验LLM的额外价值：优先让其在较慢频率提供仓位目标和紧迫度，由同一确定性执行器负责数值约束。规则、统计与LLM共享制度；微观和宏观增益分别评分。钱包地址不等于真人心理标签，知名历史事件仍可能被模型记忆。
